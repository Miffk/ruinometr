# Руинометр — разбор матчей Dota 2

Вставляешь ID матча — получаешь, кто тащил, а кто руинил, и почему:

- **вклад** каждого игрока 0–100 относительно нормы героя и позиции;
- **линия, смерти, драки и эпизоды** с таймкодами;
- **закуп и прокачка** против про-игроков (в турбо — против турбо-игроков твоего ранга);
- **ответ на вражеский пик**;
- **AFK, деньги в кармане, пропущенные байбеки**;
- **карта матча** с проигрыванием;
- **порядочность и вежливость**.

Основные данные берутся из [OpenDota API](https://docs.opendota.com/). Свой парсер реплеев (`parser/`, Java + [clarity](https://github.com/skadistats/clarity)) достаёт то, чего у OpenDota нет: приказы игроков, позиции, золото по секундам, варды.

## Быстрый старт

Нужно:

- [Python 3.12+](https://www.python.org/downloads/). На Windows при установке отметь «Add python.exe to PATH».
- [Java 21+](https://adoptium.net/) — по желанию. Без неё разбор работает, но без AFK, карты и сигналов из реплея.

Запуск:

- **Windows:** скачай репозиторий (Code → Download ZIP или `git clone`) и запусти `run.bat`.
- **Linux / macOS:** `sh run.sh`.

Первый запуск сам поставит зависимости и соберёт парсер. Сайт откроется на http://127.0.0.1:8000: вставь ID матча или ссылку с Dotabuff, OpenDota или Stratz.

Первый разбор матча занимает несколько минут: OpenDota разбирает реплей, а сайт собирает про-матчи для сравнения. Повторно — мгновенно, всё кэшируется в `data/`.

Из консоли:

```bat
.venv\Scripts\python.exe -m ruiner.cli 9046870406
```

## Что в разборе

- **Ход матча**: преимущество по золоту и опыту по минутам, снесённые строения, Рошан, чат.
- **Позиции 1–5**: оценка OpenDota (`position_est`). Соперник по линии: 1↔3, 2↔2, 4↔5.
- **Эпизоды**: правила над фактами. Слил или выиграл линию к 10:00, «жил в таверне», главный фидер, смерти в соло вне драк, байбек с повторной смертью, явка на драки, вардмастер, главный дамагер.
- **Руинометр 0–100**: взвешенная сумма компонентов. Процентили GPM/XPM/добиваний/урона по герою (benchmarks OpenDota), участие в убийствах, смерти и время мёртвым, линия, доля нетворса для коров, вижн и контроль для саппортов, **закуп против про**. Веса лежат в `ruiner/analysis/scoring.py`.
- **Закуп против про**: берутся свежие матчи лиг на том же герое (`/heroes/{id}/matches`). Если таких игр хватает, только на той же позиции. По ним считаются доля игр с предметом и тайминги (медиана, 25-й и 75-й процентили). Отмечается:
  - **поздний предмет**: позже 75-го процентиля про больше чем на 2 минуты;
  - **не собранный коровой предмет**: про берут его в 40% игр и больше, а матч длился достаточно;
  - **покупка вне меты**: предмет есть у про реже чем в 12% игр.
- **Ответ на пик врага** (`ruiner/analysis/counters.py`): правила «против этого обычно покупают это».
  - **Уклонение**: PA, Windranger, Brewmaster или купленный Butterfly → керри нужен MKB или Bloodthorn.
  - **Много контроля**: 3+ героя из своего списка → керри и миду нужен BKB или Linken's.
  - **Пассивки**: Bristleback, Spectre, Huskar… → кому-то из коров нужен Silver Edge.
  - **Иллюзии**: PL, Naga, TB… → кору нужен урон по площади.
  - **Лечение**: Necrophos, Alchemist… → команде нужен антихил.
  - **Невидимость**: Riki, Clinkz, Shadow Blade… → команде нужен детект.

  Это эвристики, эпизоды помечены «Спорно». В руинометре — компонент «Ответ на пик».
- **Прокачка против про** (`ruiner/analysis/skills.py`): на тех же про-матчах.
  - **Какой навык максил первым**: тот, в который ушло больше очков за первые 9 уровней.
  - **Уровни ульта**: сравниваются с номером очка прокачки, на котором ульт берут про, а не с 6/12/18. Таланты и уровни без очков сдвигают нумерацию.
  - **Таланты по ярусам**.

  Эпизоды прокачки снижают оценку, но сами по себе не делают вердикт «Под вопросом».

- **Поряда (свой парсер)**: реплей качается с серверов Valve (сейчас он сжат zstd, хотя файл называется `.dem.bz2`), разбирается и удаляется, остаётся `data/replays/{id}.parsed.json` (~1 МБ).
  - **AFK («Отошёл за чаем»)**: от 90 с подряд без единого приказа, пока герой жив. Время мёртвым не считается. Если герой за это время не сдвинулся, помечается «стоял на месте». Входит в руинометр компонентом «Присутствие в игре».
  - **Порядочность и вежливость**: уровни из `CDOTA_PlayerResource` на момент матча. Уровни, сверенные с battlepass, показываются полосой («10 000+», «8 000–10 000»), остальные — номером уровня.
  - **Таблица после смерти**: после скольких смертей игрок открывал панель статистики (`m_iStatsPanel`), пока ждал респаун. Это наш сигнал: со счётчиком battlepass он не совпадает, их метод неизвестен.
  - **Токсичный чат**: грубый фильтр мата и оскорблений в общем чате.
  - **Деньги в кармане**: смерть с 2000+ непотраченного золота сверх запаса на байбек (с 20-й минуты).
  - **Умер с откатанным предметом**: смерть в драке, когда BKB, Glimmer, Force Staff, Eul's и т. п. были в инвентаре и не использованы за время их перезарядки. Применения берутся из боевого лога реплея. Blink не считается: после урона он недоступен.
  - **Не выкупился**: падала база (t3, t4, барак), до респауна было 15+ с, золота на байбек хватало, а байбек не нажат.
- **Карта матча**: схема с линиями через башни и условной рекой. По координатам из реплея на ней показаны:
  - строения со временем сноса;
  - варды с радиусом обзора;
  - герои раз в 2 секунды и следы за последнюю минуту;
  - смерти.

  Есть ползунок времени, проигрывание ×10–×120 и ссылка «на карте» у каждого эпизода.

## Турбо

Если матч в турбо (`game_mode = 23`), весь разбор идёт по турбо-меркам ([turbo.py](ruiner/analysis/turbo.py), [mode.py](ruiner/analysis/mode.py)):

- **С кем сравниваем.** SQL-обозреватель OpenDota находит свежие турбо-матчи с тем же героем на вашем ранге (той же медали, при нехватке — ±1 медаль). Берётся по 15 игроков на героя, без ливеров, игры от 15 минут.
- **Нормы руинометра** (процентили GPM, XPM, добиваний, урона, лечения, урона по строениям) считаются по этой выборке, а не по benchmarks OpenDota: те не учитывают режим. Например, 1263 GPM на Anti-Mage в турбо — это 53-й процентиль, а по обычным нормам вышел бы почти максимум.
- **Закуп и прокачка** — что собирают и как качают турбо-игроки в играх похожей длины. Таймингов покупок в турбо-выборке нет: OpenDota не разбирает эти матчи. Поэтому тайминги — оценка: медиана про × темп турбо, со значком «≈». «Поздно» ставится только с большим запасом: позже оценки × 1,5 + 2 минуты, для предметов от 5 минут, которые турбо-игроки берут хотя бы в 30% игр.
- **Темп турбо** считается для каждого героя по данным: медианный GPM в обычных играх / медианный GPM в турбо-выборке. Обычно выходит 0,4–0,5.
- **Окна и пороги масштабируются темпом:**
  - линия — до 5–8 минут вместо 10, финал — последние 3 минуты;
  - «деньги в кармане» — от 2000 / темп золота;
  - запас на байбек — с 20 × темп минуты;
  - пороги «камбэка» и «разгрома» по золоту — делённые на темп;
  - минимальная длина матча для «ответа на пик» — умноженная на темп.

Первый разбор турбо-матча дольше: к про-мете добавляется до ~150 запросов за турбо-матчами. Дальше всё берётся из кэша. Размер выборки задаёт `RUINER_TURBO_SAMPLES`.

## Парсер реплеев

Нужна Java 21+. `run.bat` и `run.sh` при первом запуске сами соберут `parser/target/ruiner-parser.jar`. Maven ставить не нужно: его скачает Maven Wrapper (`parser/mvnw`). Вручную:

```bat
parser\mvnw.cmd -q -f parser\pom.xml package -DskipTests
java -jar parser\target\ruiner-parser.jar parse data\replays\<id>.dem out.json
```

Режимы `explore` и `changes` — разведка: какие сообщения, события и свойства сущностей есть в реплее. Пригодятся, когда Valve что-то поменяет.

Если Java или парсера нет, или реплей уже удалён у Valve, разбор строится без этих данных, а на странице сказано почему.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OPENDOTA_API_KEY` | — | Ключ OpenDota: снимает лимит ~60 запросов в минуту |
| `RUINER_PRO_SAMPLES` | 10 | Сколько про-матчей на героя брать для сравнения закупа |
| `RUINER_DATA` | `./data` | Где хранить кэш |
| `JAVA_BIN` | `java` из PATH | Какую Java запускать для парсера |
| `RUINER_PARSER_JAR` | `parser/target/ruiner-parser.jar` | Путь к собранному парсеру |

Первый разбор матча занимает 2–3 минуты: для 10 героев грузится около сотни про-матчей. Дальше всё берётся из кэша в `data/cache`. Мета героя обновляется раз в 12 часов.

## Ограничения

- С патча 10.07.2026 Valve не пишет в реплей, кто кого репортил. Узнать это нельзя ни здесь, ни на других сайтах.
- Реплеи хранятся у Valve ограниченное время. Старый матч разберётся только по данным OpenDota.
- Если OpenDota ещё не разобрал матч, сервис сам ставит его в очередь и ждёт до 6 минут.
- Про играют в другом темпе. Опоздание с предметом на пару минут в паблике — нормально, поэтому такие эпизоды помечены как «Спорно».
